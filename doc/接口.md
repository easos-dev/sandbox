# 沙箱运行器接口

HTTP/1.1，请求与应答都是 JSON（`Content-Type: application/json`）。除 `GET /healthz` 外每个请求都要两个请求头：

| 头 | 说明 |
| --- | --- |
| `Authorization: Bearer <密钥>` | 密钥来自环境变量 `SANDBOX_API_KEY`（或 `_FILE`）；错误或缺失 → 401 `unauthorized` |
| `X-User-Id` | 命名空间账号名：`^[a-z0-9][a-z0-9-]{0,31}$`；首次出现时建账号；不合法 → 400 `namespace_invalid`，撞上系统账号 → 403 `namespace_reserved` |

公共参数：`conversation_id` 为 `^[A-Za-z0-9_-]{1,64}$`（400 `conversation_invalid`）；`path` 相对会话目录，
规范化后拒绝 `..`、绝对路径、反斜杠、NUL、超过 1024 字节（400 `path_invalid`），`.` 与连续斜杠忽略。
运行器打开路径时每一级都不跟随符号链接，经过符号链接或目标不是普通文件也是 400 `path_invalid`。

## 错误应答

统一形状，HTTP 状态码按下表；有附加字段时并列在同一对象里（例如 `failed_part`、`upstream_status`）。

```json
{"error": "too_large", "message": "文件超过 max_bytes（1048576 字节）", "size": 2000000, "max_bytes": 1048576}
```

| 状态 | `error` | 何时 |
| --- | --- | --- |
| 400 | `bad_request` | 参数缺失或取值不合法（含 `body_invalid`：请求体不是预期 JSON 或超过 4 MiB） |
| 400 | `namespace_invalid` / `conversation_invalid` / `path_invalid` / `range_invalid` | 对应字段不合法；`range_invalid` 带 `size` |
| 401 | `unauthorized` | 密钥错误或缺失 |
| 403 | `namespace_reserved` | `X-User-Id` 对应的系统账号不是沙箱建立的 |
| 404 | `route_not_found` / `execution_not_found` / `conversation_not_found` / `not_found` | 接口、执行号、会话目录、文件不存在 |
| 413 | `too_large` | 下载超过 `max_bytes`，带 `size`、`max_bytes` |
| 502 | `upstream_failed` | 连不上下载地址、下载中断、跳转超过 3 次 |
| 502 | `upstream_status` | 下载地址返回非 2xx，带 `upstream_status`、`upstream_body`（前 300 字节） |
| 502 | `upload_failed` | 上传某段失败，带 `failed_part`（0 起）、已完成段的 `parts`，上游有应答时还带 `upstream_status`、`upstream_body` |
| 500 | `internal` | 运行器自身错误（建账号失败、写文件失败等），`message` 说明原因 |

## GET /healthz

不需要鉴权。应答 `{"ok": true}`。

## 命令

### POST /execute?wait=<秒>

开始一条命令。`wait`（0～30，默认 0，超过 30 按 30）：最多等这么久，命令结束或有输出就返回。

请求：

```json
{"conversation_id": "c0q7cx1gpb9y6", "command": "python3 analyze.py in/data.csv", "timeout": 600}
```

| 字段 | 说明 |
| --- | --- |
| `command` | 交给 `bash -c` 的文本，非空，≤ 256 KiB |
| `timeout` | 可选，秒，1～600，默认 600，超过 600 按 600；到期按进程组先 TERM 两秒后 KILL |

应答（状态对象，下面三个接口都返回它）：

```json
{
  "id": "3f9a1c2e7b6d4e01",
  "conversation_id": "c0q7cx1gpb9y6",
  "status": "running",
  "exit_code": null,
  "output": [{"stream": "combined", "data": "正在读取 in/data.csv …\n"}],
  "next_offset": 31,
  "total_bytes": 31,
  "truncated": false,
  "output_path": "out/3f9a1c2e7b6d4e01.txt",
  "started_at": 1792261359254,
  "finished_at": null,
  "message": null
}
```

| 字段 | 说明 |
| --- | --- |
| `id` | 执行号，16 位小写十六进制 |
| `status` | `running`、`done`（看 `exit_code`）、`timeout`、`killed`、`failed`（等待进程出错）、`unknown`（运行器在它结束前重启过） |
| `exit_code` | 进程退出码；被信号结束时为 128+信号号（如 143 = TERM、137 = KILL）；未结束为 null |
| `output` | 本次新给出的输出：标准输出与错误合并成一条流，范围是 `[max(offset, total−16 KiB), total)`；没有新输出时为空数组 |
| `next_offset` | 下次查询应带的 `offset`（等于 `total_bytes`） |
| `truncated` | 本次应答跳过了 `offset` 到尾部开头之间的字节（它们只在 `output_path` 文件里） |
| `output_path` | 完整输出文件，相对会话目录 |
| `started_at` / `finished_at` | Unix 毫秒 |
| `message` | 异常说明（`unknown`、`failed` 时有） |

### GET /execute/{id}/status?wait=<秒>&offset=<字节>

查状态。`offset` 是上次应答的 `next_offset`（默认 0，超过总长时返回空输出）；`wait`（0～30，默认 0，超过 30 按 30）：命令还在跑且 `offset` 之后没有新输出时最多挂这么久。
执行号属于别的命名空间或不存在 → 404 `execution_not_found`。已结束很久、不在内存里的执行从记录与 `out` 文件回答，`output` 仍是尾部。

### DELETE /execute/{id}

停止：按进程组发 TERM，两秒后 KILL，等它真的结束再返回状态对象（`status` 为 `killed`）。已结束的直接返回终态。

## 文件

### POST /files/download

运行器自己下载到会话目录。只接受 http/https，跟随至多 3 次跳转，不带任何凭证头。
先看 `Content-Length`，再边收边数，超过 `max_bytes` 即中止并删掉临时文件；成功才改名到目标路径（覆盖已有文件）。中间目录自动建立。

```json
{"conversation_id": "c0q7cx1gpb9y6", "url": "https://cdn.example.com/x/abc.webp", "path": "in/photo.webp", "max_bytes": 104857600}
```

应答：

```json
{"path": "in/photo.webp", "size": 48213, "mime": "image/webp", "content_type": "image/webp", "final_url": "https://cdn.example.com/x/abc.webp"}
```

`mime` 是运行器按文件头与扩展名推断的（与 `stat` 同一规则）；`content_type` 是上游应答头原文，可能为 null。

### POST /files/stat

一遍流式算出指纹。

```json
{"conversation_id": "c0q7cx1gpb9y6", "path": "out/report.xlsx"}
```

```json
{
  "path": "out/report.xlsx",
  "size": 6291456,
  "mime": "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet",
  "md5": "0cc175b9c0f1b6a831c399e269772661",
  "etag": "a3c6…-2",
  "crc64_ecma": "11051210869376104954",
  "crc64_nvme": "12587734210516281480",
  "part_size": 5242880,
  "parts": [
    {"offset": 0, "length": 5242880, "md5": "…", "crc64_nvme": "…"},
    {"offset": 5242880, "length": 1048576, "md5": "…", "crc64_nvme": "…"}
  ],
  "modified": 1792261359254
}
```

| 字段 | 说明 |
| --- | --- |
| `md5` | 整个文件的 MD5，小写十六进制 |
| `etag` | File 的"内容 ETag"：按 5 MiB 分片，一片时等于 `md5`，多片时是各片 MD5 拼接再 MD5 加 `-片数` |
| `crc64_ecma` / `crc64_nvme` | CRC-64/XZ（OSS）与 CRC-64/NVME（S3/MinIO），十进制字符串，与 File 库里的存法一致 |
| `parts` | 每片的位置、MD5（填分片 PUT 的 Content-MD5 时转 base64）与 CRC-64/NVME 十进制（S3/MinIO 分片上传时 File 签进这一片的请求头） |
| `mime` | 推断：魔数 → 扩展名 → UTF-8 文本判断 → `application/octet-stream` |
| `modified` | 文件修改时间，Unix 毫秒 |

### POST /files/prove

秒传持有证明：对每段算 `HMAC-SHA256(key = hex_decode(nonce), 段字节)`，十六进制。`nonce` 必须是非空十六进制（File 挑战里的 nonce 就是）。
最多 64 段、总长 ≤ 16 MiB；段超出文件 → 400 `range_invalid`。

```json
{"conversation_id": "c0q7cx1gpb9y6", "path": "out/report.xlsx", "nonce": "9f1c…", "ranges": [{"offset": 1048576, "length": 65536}, {"offset": 3145728, "length": 65536}, {"offset": 5000000, "length": 65536}]}
```

```json
{"path": "out/report.xlsx", "size": 6291456, "proofs": ["5bdc…", "a1e2…", "77f0…"]}
```

### POST /files/upload

按助手交来的计划逐段发出。每段把文件 `[offset, offset+length)` 以 `method`（`PUT` 默认或 `POST`）发到 `url`，带 `headers`；
运行器自己算 `Content-Length`（计划里的 `Content-Length`、`Transfer-Encoding` 忽略），请求体流式读文件，不整段进内存，不跟随跳转。
段按顺序一段段发，任一段失败就停在那一段。最多 10000 段；段超出文件 → 400 `range_invalid`。

```json
{
  "conversation_id": "c0q7cx1gpb9y6",
  "path": "out/report.xlsx",
  "parts": [
    {"offset": 0, "length": 5242880, "url": "https://bucket.oss.example.com/obj?partNumber=1&uploadId=…&signature=…",
     "headers": {"Content-Type": "application/octet-stream", "Content-MD5": "DMF1ucDxtqgxw5niaXcmYQ=="}},
    {"offset": 5242880, "length": 1048576, "url": "https://bucket.oss.example.com/obj?partNumber=2&…", "headers": {"Content-MD5": "…"}}
  ]
}
```

成功：

```json
{"path": "out/report.xlsx", "size": 6291456, "parts": [
  {"offset": 0, "length": 5242880, "status": 200, "etag": "\"0cc175b9c0f1b6a831c399e269772661\""},
  {"offset": 5242880, "length": 1048576, "status": 200, "etag": "\"…\""}
]}
```

失败（第二段被拒）：

```json
{"error": "upload_failed", "message": "第 2 段上传返回 HTTP 403", "failed_part": 1, "upstream_status": 403, "upstream_body": "<Error>…", "parts": [{"offset": 0, "length": 5242880, "status": 200, "etag": "\"…\""}]}
```

### DELETE /conversations/{id}

先停掉该会话还在跑的命令、删掉它们的执行记录，再以命名空间账号自己的身份 `rm -rf` 整个会话目录。

```json
{"conversation_id": "c0q7cx1gpb9y6", "deleted": true}
```

目录本来就不存在时 `deleted` 为 false。

## 没有的接口

读文件、写文件、列目录、取字节、上传字节：都没有，也不会加。文本内容走 `execute`；文件进出走 `download` 与 `upload`。
